🔐 Azure Key Vault: dp-kv-deliverypilot

Every server-side secret behind the notes widget and the chat agent lives in one Azure Key Vault. The Function App reads them through Key Vault references, so the code only sees ordinary environment variables and nothing sensitive is committed to this repo or shipped to the page.

Verification status: the requirements marked Implemented are visible in this repo's code. Those marked Operational are Azure settings that this repo cannot prove, and Proposed ones aren't built. The vault was not read when this page was written, because the available Azure token had expired.

✅ Requirement checklist

📘 Runbook

Deploy with Key Vault secrets

./scripts/deploy.sh --all

Fetches all required secrets from dp-kv-deliverypilot, syncs them to Fly.io secrets, configures Azure Function references, and deploys both services.

Get the admin token for the dashboard widget

az keyvault secret show --vault-name dp-kv-deliverypilot -n CC-ADMIN-TOKEN --query value -o tsv

Grant the Function App's managed identity access (KV-3)

az functionapp identity assign -g <resource-group> -n <function-app>
az role assignment create --assignee <principalId> --role "Key Vault Secrets User" \
  --scope $(az keyvault show -n dp-kv-deliverypilot --query id -o tsv)

Confirm references resolve

Portal: Function App → Environment variables → the status column of each Key Vault reference should say Resolved.

Rotate a secret

az keyvault secret set --vault-name dp-kv-deliverypilot -n <name> --value "<new value>"

References pick up the new version within about a day; restart the Function App to force it. After rotating CC-ADMIN-TOKEN, paste the new token into the widget.

🕳️ Known gaps

  • There is no infrastructure-as-code in this repo, so KV-3, KV-8 and KV-11 must be checked in Azure.
  • CC_ADMIN_TOKEN sits in the browser's localStorage, so an XSS on this Pages origin would expose it. Keep note content escaped and rotate the token if the page is ever compromised.
  • The stats scripts have no subscriber or watch-hours source. KV-12 proposes a YOUTUBE-API-KEY secret for public subscriber counts; watch hours still need YouTube Studio or the OAuth-based Analytics API.
