## 1. 🧭 What this site is

A static dashboard for a YouTube + Skool content business. It has ~34 HTML pages, each rendered in the browser from JSON in `data/`. There is no build step. Pages use Tailwind via CDN and load shared scripts from `assets/`.

## 3. ✅ Checklist for every new or edited page (tests enforce most of it)

1. **🙂 Emojis:** every `h1`/`h2` starts with a fitting emoji. Use emojis in status text and labels too.
2. **🖼️ Favicon:** an emoji SVG `<link rel="icon">` right after `<title>`, using an emoji no other page uses.
3. **📐 Diagram:** add the page to `data/diagrams.json` (title + emoji steps, optional `loop`). Use `"builtIn"` only if the page draws its own chart or diagram.
4. **📖 Guide:** list the page in `data/guide.json` in the right step, with a one-line `why`.
5. **🔗 Links both ways:** add at least 2 pairs to `data/guide.json` → `links` (`[a, b, reason]`). They're undirected, so every link has a link back.
6. **🧩 Shared scripts** (in this order, before `</body>`): `cc-widget.js` (with `data-api="/api"`), `cc-notifications.js`, `cc-guide.js`, `cc-diagram.js`, `cc-pagenav.js`, `cc-footer.js`.
7. **🔍 Search:** add an entry to `assets/cc-search.js`.
8. **🧭 Menu:** add a link in the right dropdown in `index.html` (Plan, Results, Reports, Goals, Strategy, Docs).
9. **🆕 What's new:** add a line to `data/guide.json` → `whatsNew` (newest first, keep about 8).
10. **📱 Phone width:** check the page at phone width. No horizontal scroll, and no text clipped or overlapping.

## 4. ✍️ Content rules

- **Never invent facts about Erdem.** Use only what's in `data/story.json` and the other "who" files, or what he says in chat. When something is unknown, leave a visible placeholder (e.g. "✍️ add your note") instead of guessing.
- **Label assumptions.** Prices, forecasts and positions on charts are marked as assumptions or judgements, not facts.
- **Honest about AI:** separate what the evidence shows from predictions ("a model, not a promise"). Frameworks like Hawkins' map are presented as frameworks, not science.
- **Verify before citing:** check a YouTube handle exists before linking it, and compute any ratio before stating it.
- **Original characters only:** formats inspired by La Linea, Roger Rabbit or Star Trek borrow the technique, never the characters, names, logos or catchphrases.
- **Voice:** plain English, direct, optimistic and practical. One message: the Delivery Pilot.

## 5. 🎬 Video planning rules

- **WIP limit: 3 videos per week** in progress (planned, writing, filming or editing). Adding one means swapping one out in the same week.
- **One upload per day at most.** Two on the same day split the audience.
- **Two pillars work** (see `what-works.html`): ① practical, cost-saving dev tooling ② grounded, data-backed career/industry takes. Mindset Shorts and narrow commentary don't work.
- **Do not edit `data/videos.json` plan items in reports.** Put plan changes in the reports' "next" / "actions" as suggestions.

## 6. 📑 Weekly reports

- The cloud routine "Weekly content reports" runs **Mondays 08:00 UTC**. It runs `scripts/weekly_reports.sh`, then rewrites `week-review.json`, `performance-insights.json` and `what-works.json` from the fresh numbers.
- `scripts/weekly_reports.sh` also runs `scripts/build_guide.py`, which dates each page for the Guide's "Recently updated" list.

## 7. 🤖 The dashboard chat agent

- The browser chat posts to `/api/chat`, which goes to an Azure Function queue job. The job runs in the **Fly.io Sprite `cc-agent`**: the repo and Claude Code are already there, and each job gets its own git worktree.
- Sprite calls **retry** 429/502/503/504 with backoff. If the sprite never comes up, the job falls back to **Daytona**.
- After the agent edits files, the harness commits, opens a PR, **squash-merges into `main`, deletes the branch**, and waits for the deploy. The chat shows each step with an emoji and a timer.
- The chat agent **edits files only**: no git, gh or fly. It never touches `api/`, `server/` or `.github/` (those are changed by a person, through a reviewed commit).

## 8. 🌳 Git & deploy: trunk-based

- Work on **`main` only**, and keep it the only branch. Delete any merged branch.
- After every change: run the tests → commit → `git pull --rebase` → push → **watch the deploy** → **check the change on the live site**.
- Pushing to `main` deploys automatically: "Deploy to Fly.io" for the site, and "Deploy with Azure Key Vault" for `api/` and `server/`. The deploy stamps `data/deploy.json` (time + commit), which the footer shows.
- Put `[chrome]` in a commit message when it only touches shared page furniture on many pages, so the Guide's "Recently updated" list ignores it.
- End commit messages with the co-author line the session asks for.

